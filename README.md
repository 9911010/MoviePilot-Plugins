# MoviePilot V3 图片维护插件

本仓库提供两个可独立安装、配置、停用的插件。它们没有运行时依赖，检查范围不重叠。

| 插件 | 范围 | 默认调度 |
| --- | --- | --- |
| 合集封面同步 CollectionCoverSync | BoxSet 合集主海报 | 每 6 小时检查合集 |
| 影视图片修复 MediaImageRepair | Movie、Series、Season、Episode 的 Primary 图片 | 每 6 小时检查 500 项并接续位置 |

## 影视图片修复

独立安装「影视图片修复」，配置 Emby 服务地址和 API Key，选择媒体类型，可限定一个媒体库 ID。首次使用建议只检查一批，再开启修复。默认 Cron `43 */6 * * *`，与合集任务错开；单次最多 2000 项、默认 500 项，逐项处理，约一万项媒体需五天左右完成一轮。列表排序期间新增/删除条目可能导致本轮漏查或重复，下轮会再次遍历。

只使用 Emby 当前匹配条目的 TheMovieDb 主图片候选。Emby 自身需有正确的 TMDB 匹配与图片提供器配置；插件不搜索片名、不更改媒体 ID，不需要另外填写 TMDB 密钥。代理仅用于下载 TMDB 图片；Emby 自身查询候选图使用它自己的网络设置。

- 正常图片不覆盖；已锁定条目跳过。
- 图片完整解码校验，HTML 错误页即使返回 200 也不会当作正常图片。
- 只有成功读取图片清单且没有 Primary，或图片读取明确返回 404，才视为缺图。鉴权失败、超时及有图片记录时的 500 只记录错误。
- 没有 TMDB 候选时跳过，下一轮再次检查，不用不相干图片硬填。
- 写入前再次检查，避免覆盖刚刚手工补入的图片；先保存备份，再上传并验证。
- 修复缓存按服务器及媒体身份隔离；正常图片备份默认关闭，可单独开启，大型库会占用较多磁盘。
- 每批检查位置持久化，停用后停止写入。只检查模式单独记录位置，不上传图片。
- 数据页保留最近 20 批结果。停用不会删除服务器图片。

范围仅包括主图片：单集的 Primary 通常是该集缩略图。不处理 Backdrop、Logo、Banner，不触发全库刮削，也不能代替修复上游同步配置。周期检查属于补救措施，不保证阻止其他工具再次写坏文件。

运行测试：`python -m unittest discover -s tests/v3/mediaimagerepair -v`。

# 合集封面同步 · MoviePilot V3

`CollectionCoverSync` 定期检查 Emby 的合集主海报，按合集的 TMDB 编号补齐缺图。它保留能正常解码的已有封面，包括用户手工挑选的海报；不修改电影/剧集信息、不重建合集、不触发全库刮削。

## 功能

- 默认每 6 小时检查（Cron：`17 */6 * * *`，MoviePilot 所设时区）。
- 支持保存配置后立即运行，或“仅检查、不上传”。
- 即便图片接口返回 HTTP 200，也会完整解码图片，拒绝将 HTML 错误页当作海报。
- 404 视为缺图；超时、401/403、5xx 保留现状并记录错误，下次周期再检查。
- 有效现有海报会备份到插件数据目录。以后缺图时优先恢复备份，保护手工海报。
- 下载新图后、上传前再次检查现有图片，避免覆盖期间手工补入的海报。
- 只根据 `ProviderIds.Tmdb` 的合集 ID 查找。缺少编号会记录并跳过，不猜测片名。
- 分页读取合集，单任务串行运行，任务之间防重入；停用后取消待执行任务，进行中的请求结束后停止。
- 最近 20 次检查明细保存在插件数据中，详情页显示最近一次结果。

## 安装与配置

将本仓库的 GitHub 地址添加到 MoviePilot 插件仓库列表，选择 **合集封面同步** 安装。市场读取 `main` 分支上的 `package.v3.json` 和 `plugins.v3/collectioncoversync/`。

插件配置：

| 配置 | 用途 |
| --- | --- |
| Emby 服务地址 | 例如 `http://nas:8096`；可带 `/emby`，优先使用 MP 容器可访问的内网地址 |
| Emby API Key | 具有读取合集、读取图片和上传图片权限的现有服务器密钥 |
| 限定合集父目录 ID | 通常留空；如需仅检查某个合集目录，填写该目录 ID |
| TMDB API Key / Read Access Token | 可选。填写则使用官方合集 API；留空读取公共合集页 |
| TMDB 专用 HTTP 代理 | 可选，只影响 TMDB；Emby 请求直接连接。留空时 TMDB 使用运行环境代理 |
| 修复无法解码的损坏图片 | 默认开启。关闭后仅补缺图，损坏图片只报告 |
| 仅检查 | 验证和备份有效图片，报告待补/待修复，不上传图片 |
| 启用定期检查 | 开启后由 MP 调度器注册周期服务 |
| 保存后立即运行一次 | 保存后自动复位，交由 MP 一次性任务调度器执行 |

建议首次勾选“仅检查”和“立即运行一次”，确认详情页的合集范围与结果，再关闭“仅检查”并启用周期检查。

TMDB 公共页面可能调整结构或限制请求。可配置自己的 TMDB API Key 提高稳定性；公共页面请求受限时，若容器已有 `curl`，插件会使用它作一次有超时、大小限制的下载尝试。不会自动安装系统软件、绕过验证码或关闭 TLS 校验。

TMDB 合集页有时本身使用单部影片风格海报，插件按该合集页现有选择同步，不生成海报、不用成员影片海报兜底。只同步主海报，暂不管理背景图、Logo、名称、简介、演职人员或剧集缩略图。

## 备份与停用

数据保存在 MoviePilot 分配的插件数据目录，按服务器地址哈希隔离；配置和密钥仅保存在 MP 插件配置。正常图片缓存有内容校验，损坏原文件另存到 `damaged/` 供排查。

停用插件会停止后续检查，不删除 Emby 海报或备份。不要在仍需恢复原手工海报时清空插件数据目录。不同媒体服务器需要分别配置插件实例，避免同一服务器重复启用多个同步实例。

## 开发验证

源码遵循 [MoviePilot V3 插件指南](https://github.com/jxxghp/MoviePilot-Plugins/blob/main/docs/Plugin_Development.md)，采用 `app.sdk.*` 入口、宿主管理的定时服务与一次性任务。

```sh
python -m unittest discover -s tests/v3/collectioncoversync -v
python -m compileall plugins.v3/collectioncoversync
```

单元测试使用明确的 MP 宿主桩，不代表已在真实 MP 加载成功。发布/安装后仍需验证：插件出现在我的插件、配置能保存、周期服务已注册、立即运行生成记录、停用后服务消失。

截至 2026-10-30 的本地验证：26 项离线测试通过；实际 Emby 18 个合集只读检查全部正常；实际 TMDB 阿凡达合集海报下载/解码通过。该检查没有向实际 Emby 上传图片。实际 MP 安装验证结果以部署记录为准。

配套 Codex skill 位于 `skills/emby-collection-covers/`，用于后续维护；自动同步由 MP 插件执行，不依赖 Codex 常驻。
